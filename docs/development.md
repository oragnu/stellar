# Local development

## Prerequisites

- Python 3.12+ and [`uv`](https://docs.astral.sh/uv/)
- Node.js 22+ and npm
- PostgreSQL 16 (via Docker is easiest — see below — or a local install)
- A [GitHub OAuth App](https://github.com/settings/developers) — set the
  callback URL to `http://localhost:8000/api/v1/auth/github/callback`

## 1. Start Postgres

```bash
docker run -d --name stellar-db -p 5432:5432 \
  -e POSTGRES_DB=stellar -e POSTGRES_USER=stellar -e POSTGRES_PASSWORD=stellar \
  postgres:16-alpine
```

(Or reuse `docker/docker-compose.yml`'s `db` service alone: `docker compose --env-file .env -f docker/docker-compose.yml up db`.)

## 2. Backend

```bash
cd backend
uv sync                                  # installs deps into backend/.venv
cp ../.env.example ../.env               # then edit ../.env:
#   DATABASE_URL=postgresql+asyncpg://stellar:stellar@localhost:5432/stellar
#   GITHUB_CLIENT_ID / GITHUB_CLIENT_SECRET from your OAuth App
#   SECRET_KEY / SECRET_ENCRYPTION_KEY — generate per the comments in .env.example
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000
```

Backend is now at `http://localhost:8000`; interactive API docs at
`http://localhost:8000/docs`; health check at
`http://localhost:8000/api/v1/health`.

## 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Vite dev server runs on `http://localhost:5173` and proxies `/api/*` to the
backend on `:8000` (see `frontend/vite.config.ts`). Sign in via the landing
page — the OAuth flow redirects through the backend, then back into the SPA.

## Running tests

```bash
# Backend
cd backend
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run mypy app

# Frontend
cd frontend
npm run test           # vitest — unit tests, tests/unit/
npm run lint           # eslint
npx tsc --noEmit

# E2E (needs the full stack up first — see "Full stack via Docker" below)
cd frontend
npx playwright install --with-deps chromium   # first time only
BASE_URL=http://localhost:8000 npx playwright test   # tests/e2e/
```

`tests/unit` (Vitest) and `tests/e2e` (Playwright) are deliberately
separate runners/directories — `frontend/playwright.config.ts` scopes
Playwright to `tests/e2e` specifically, since without that it also picks
up (and crashes on) the Vitest specs.

## Database migrations

```bash
cd backend
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Always review autogenerated migrations before committing — Alembic is
good but not infallible, especially around renamed columns/tables.

## Full stack via Docker (closest to production)

```bash
docker compose --env-file .env -f docker/docker-compose.yml up -d --build
```
